# Session 2026-04-06: Performance, Icons, UI Polish

## What Was Done

### Performance Optimization
- **Terrain RenderTexture** — replaced ~2200 individual tile sprites with a single baked RenderTexture (1 draw call vs 2200)
- **Progressive map generation** — split into 3 packs:
  - Pack 0 (sync): center 800px terrain + player + physics — instant first frame
  - Pack 1 (next frame): mid-range terrain 800-1600px + decorations/rocks zones 0-2
  - Pack 2 (deferred): outer terrain + far decorations + grave textures
- **Lazy hero loading** — only the selected hero's spritesheets are loaded (was loading all 7 = ~50 spritesheets)

- **Boss scale reduced** x7 → x5, delayed appearance by 2s on StartScene

- **Spritesheet upgraded**: 32x32 → 128x128 per frame for quality at large display sizes
- Fire consecration icon patched into both `aq1_titans_pulse` (frame 55) and `as2_consecration` (frame 66)

## Lessons Learned

### Icon Spritesheet Mapping
**Never derive frame indices from runtime data structures.** The order of upgrades in TS code has no relationship to the order of icons in a spritesheet generated by a separate Python script. Always use a static map that matches the actual asset layout.

### Progressive Loading > Loading Bars
A loading bar signals "wait" — progressive generation eliminates the wait entirely. For tile-based terrain, bake visible area first (sync), then expand outward in deferred frames. User perceives instant load.

### RenderTexture for Static Terrain
Individual tile sprites = N draw calls every frame forever. RenderTexture = N draw calls once during setup, then 1 draw call per frame. For a 3000x3000 map with 64px tiles, this is ~2200 draw calls eliminated per frame.

### Procedural VFX > Spritesheet VFX
The frost aura spritesheet was 1.4MB, 8 frames, static rotation. The procedural version uses zero assets, has dynamic breathing/scaling, and looks better because it responds to game state (aura radius changes with upgrades).

### Lazy Asset Loading
Loading all 7 heroes' spritesheets (~50 files) when only 1 is needed wastes bandwidth and GPU memory. Switch-case in preload() based on selected hero type eliminates ~85% of hero asset loading.
